# Contributing to Awesome Passive Income

Thank you for your interest in contributing. This guide explains how to add a tool, platform, guide, or case study so the list stays consistent and useful.

The curated list lives in [README.md](README.md). Add new entries there. Do not put the list back into separate pages.

## 1. How to Contribute

You can contribute in the following ways:

- **Add a tool, platform, or guide** to the matching section of `README.md`
- **Add a tutorial or case study** as a guide entry in `README.md`
- **Fix a dead link, typo, or formatting problem**
- **Suggest an improvement** by opening a GitHub issue

Before you add something, check that it is not already listed. Search the readme for the name and the URL.

## 2. Guidelines for Adding Tools

Gather this information, then turn it into the one-line format in the next section. Do not add a table to the readme.

| Field | Example |
|-------|---------|
| Name | Pictory |
| URL | https://pictory.ai/ |
| Use case | Turns scripts and articles into videos |
| Section | Video and Podcasts |
| Notes | Actively maintained, public product page |

- Put the entry in the section a reader would search.
- Keep the description to one sentence.
- Link the canonical product or documentation page, with no affiliate or tracking parameters.
- Skip the entry if the site is gone, parked, archived, or only a homepage with no lasting content.

## 3. Guidelines for Adding Tutorials and Case Studies

A tutorial or case study needs:

- A specific title
- A URL that opens the guide itself, not a blog index or a search page
- The section it belongs in
- One sentence on what the reader learns

Weak links to leave out:

- Shortened or truncated URLs
- Redirects into a pricing page or a login wall
- Community homepages used as if they were a case study
- Pages that return a not-found response

## 4. Entry Format

Every entry in `README.md` must look like this:

```markdown
- [Pictory](https://pictory.ai/) - Turns scripts, articles, and slides into videos.
```

Rules for that line:

- Use `-`, then a space, then the link, then ` - `, then the description.
- Use a normal hyphen, not an en dash or em dash.
- Start the description with a capital letter and end it with a full stop.
- Do not start the description with the name of the entry.
- Spell product names the way the project does (`YouTube`, `WordPress`, `iOS`, `GitHub`).
- Keep each entry on one line. Do not hard-wrap it.
- Only list something you can recommend. A shorter list is better than a complete one.

Only submit a resource that is:

- Real, and still maintained
- Useful for earning income that continues after the setup work
- Something you checked by opening the link

## 5. Pull Requests

1. Open `README.md` and add the entry at the end of the right section.
2. If you add a new section, add it to `Contents` with the same wording as the heading. Do not add Contributing or Footnotes to `Contents`.
3. Explain in the pull request why the resource belongs here.
4. Do not add a license section to the readme. The license is the `LICENSE` file.
